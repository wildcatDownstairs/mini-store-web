# Mini Store 商城开发提示词

你是电商产品设计师和 Vue 前端工程师。基于 ecommerce_lab 的业务关系完善 Mini Store 用户商城。目标用户是生活在日本、使用中文购物的消费者；以生活选物为内容方向。交付可点击、可刷新继续使用的完整购物流程，而不是数据库表的网页副本。项目与 admin 分开，使用 Vue 3 + Vue Router + Vite + 原生 CSS，无 UI 组件库。当前是合成 DTO Mock，禁止真实扣款、发送邮件或修改数据库。

## 功能与页面

| 路径                         | 用户任务 / 数据                                                                   |
| ---------------------------- | --------------------------------------------------------------------------------- |
| /                            | 秋日生活提案、分类入口、精选商品、食饮专题、优惠码说明                            |
| /products?q=&category=&sort= | 搜索名称/品牌/SKU，分类、品牌、有货筛选，含税价格/评分排序，分页与空状态          |
| /products/:slug              | 商品图片、品牌、文案、规格价格、可售库存、数量、收藏、评价和配送说明              |
| /favorites                   | 本地收藏和取消收藏；数据库暂未提供收藏表                                          |
| /cart                        | 按 variant 合并、数量修改、移除、金额预览、空状态、继续选购                       |
| /checkout                    | 演示身份、地址选择、标准/快捷配送、优惠码应用、订单金额确认                       |
| /orders/:publicId            | 商品/地址快照、计价拆分、付款结果与失败重试、未付取消、状态时间线、物流和已购评价 |
| /account/orders              | 按状态查看自己的订单，继续付款或查看订单                                          |
| /account/addresses           | 新增、编辑、删除、默认地址；从结算进入后有返回入口                                |
| /login                       | 进入合成示例账户，不收集真实密码                                                  |
| /account/help                | 配送、含税价格、优惠、退换货及演示范围                                            |

不添加空按钮、虚假客服、支付卡号表单、真实登录注册、无限滚动、第三方跟踪或无对应业务的营销组件。

## UI 方案及评审

颜色：白 #FFFFFF；浅蓝绿 #E3EEEA；深绿文字 #263F3D；操作色 #BF462A；辅助文字 #6E7B74；分隔线 #E5E9E5。主题是日本日常选物，因此用原色器物、帆布、茶叶等原创矢量插画建立物品感。字体为系统 Avenir Next / Hiragino Sans / PingFang SC；首页大标题使用 Songti SC / Hiragino Mincho，形成生活刊物气质，不加载外部字体。

布局草图：

```
桌面：品牌 — 搜索 — 收藏/账户/购物袋
      分类导航
      左：秋日提案文案 | 右：灯、包、杯的插画静物
      配送/选物/计价服务说明
      四个分类入口
      四个精选商品卡
      茶饮专题 → 初次优惠
手机：品牌及操作 → 搜索 → 横向分类
      文案 → 商品静物 → 两列商品
```

评审：不照搬 admin 的侧栏和密集统计卡；消费者先看到商品和使用场景。放弃奶油底/棕色按钮的惯用组合，采用蓝绿色生活空间，橙色只指示关键购买动作。主页的静物场景是唯一视觉重点，其他页面安静、左对齐。图片不依赖外链；明确标为插画示意。

## UX 与业务规则

- 可售库存 = 示例 SKU 库存 - 本浏览器订单预占。购物袋不预占；创建订单原子校验、预占并清空购物袋。
- 用户选择的是 SKU，不是 product。改规格必须同步价格、库存、SKU 和示意色；售罄不能购买。
- 商品保存税前金额；列表/详情展示含税起价，结算按行计算。食品 8%，其他 10%，仅为实验规则。
- HELLO10 税前商品满 ¥5,000 可用，10% 折扣上限 ¥1,500。按行比例向下分配，余数给最后行；各行折后计税四舍五入。
- 标准运费 ¥500，折后税前满 ¥8,000 免费；快捷 ¥900。运费为最终收费额，不再次计税。
- 订单总额 = subtotal - discount + tax + shipping；全程整数 JPY。真实 API 用 decimal/NUMERIC，不接受浏览器传来的成交金额。
- 创建订单保存商品名称、SKU、价格、税、优惠与收货地址快照。使用幂等键避免重放创建；支付失败保留 pending，成功进入 paid，重复支付受阻；仅 pending 可取消并释放预占。
- shipped/delivered 使用历史合成订单演示，不把刚付款订单自动变成已送达。付款不等于发货。
- 只有 delivered 订单的购买项可评价，一项一次，提交 pending，审核后才公开。商品静态评价明确标为合成示例，未与真实 DB 聚合。
- 数据修改先在副本完成校验，再持久化成功后替换内存；失败提示，不假成功。跨标签页 revision 检测并要求重试。演示账户不是安全边界。
- 地址使用日本格式校验；订单地址不随地址簿编辑变化。未知商品/订单给返回入口。
- 支持键盘、原生 dialog 焦点控制、可访问标签、状态消息、清晰禁用/错误、减少动态效果偏好。390px 手机不出现整页横向滚动。

## 接口接入顺序

先读取本仓 docs/api-contract.md，与 ASP.NET Core OpenAPI 核对后再替换 Mock。业务可复用，生产计价/鉴权/库存最终由后端决定。不要先铺 Redis、支付 SDK 或消息队列。实现 API 时补服务端测试，前台端到端验收需覆盖缺货、价格变更、支付失败、重复请求、越权订单访问。
